# Recall

[English](README.md) · **한국어**

**Claude Code 프롬프트 기록을 찾아보는 로컬 데스크톱 앱.**

Claude Code는 내가 무엇을 물어봤는지 검색할 수 있는 기록을 남기지 않습니다. 3주 전에 썼던 그 좋은 프롬프트 — 마침내 리팩터링을 제대로 굴러가게 만들었던 바로 그 프롬프트 — 는 다시는 찾을 수 없는 세션 기록 어딘가에 묻혀 있습니다. 그리고 Claude Code는 그 세션 기록마저 **기본값 기준 30일 뒤에 지웁니다.**

Recall이 그걸 해결합니다. 훅이 제출하는 모든 프롬프트를 로컬 SQLite에 기록하고, 백그라운드 스위퍼가 각 프롬프트에 대한 Claude의 **응답 전체**를 수집하며, 앱이 그걸 검색·태그·북마크 가능한 아카이브로 만듭니다.

**아무 버튼도 누르지 않습니다.** 프롬프트는 제출하는 즉시 나타나고, 응답은 Claude가 답하는 동안 저절로 채워집니다.

모든 것이 내 컴퓨터 안에 있습니다. Recall은 네트워크 호출을 하지 않습니다 — 텔레메트리도, 계정도, 서버도 없습니다. 웹뷰는 원격 리소스를 차단하는 CSP 아래서 돌기 때문에, **수집된 응답 안에 원격 이미지 URL이 있어도 불러오지 않습니다.**

## 무엇을 하는가

**자동으로 수집합니다**

- **모든 프롬프트** — 제출하는 순간. 커스텀 skill과 슬래시 커맨드도 포함합니다.
- **모든 응답, 완전본** — Claude가 쓴 산문, 호출한 도구, 넘긴 인자, 돌아온 결과까지. 도구 출력은 열기 전까지 한 줄로 접혀 있어서 300KB짜리 명령 출력이 눈앞을 가리지 않습니다.
- **하나의 프롬프트 = 하나의 완결된 이야기.** 백그라운드 에이전트 알림, `/skill` 실행, `!bash` 명령, ESC 중단으로 갈라진 턴이 **하나의 응답으로 다시 꿰어집니다.**
- **세션 기록 원본** — Claude Code의 보존 기간(`cleanupPeriodDays`, 기본 30일) 밖으로 복사해 Recall이 소유하는 아카이브에 보관합니다.

**찾아봅니다**

- 프롬프트와 응답을 **검색**합니다.
- **프로젝트별로 묶습니다** — 작업 디렉터리 기준으로 분류되고, 각각에 읽기 좋은 별칭을 줄 수 있습니다 (`/Users/you/dev/some-long-path` → `Payments API`).
- 아껴둘 프롬프트를 **북마크**하고 **태그**합니다. 둘 다로 필터링할 수 있습니다.
- **날짜 범위로 필터링**합니다.
- 재사용하려고 프롬프트를 **편집하고 복사**합니다.

**망가지면 알려줍니다**

수집이 멈추면 — DB가 잠기거나, 스위퍼가 죽거나, 디스크가 차면 — Recall이 **Claude Code 안에서** 알려줍니다. 앱을 일주일 동안 안 열 수도 있으니까요. [수집 상태 경고](#수집-상태-경고) 참조.

## 설치

Recall은 내 기록을 보여주는 앱이므로 기록이 쌓여야 쓸모가 있습니다. **훅을 먼저 설치하고**, Claude Code를 평소처럼 쓰다가, 앱을 실행하세요.

### 1. 훅과 스위퍼 설치

```bash
git clone https://github.com/beckryu31/recall.git
cd recall

# 스위퍼가 이 바이너리를 실행합니다. 스위퍼를 등록하기 **전에** 빌드하세요.
cargo build --release --bin recall-ingest --manifest-path src-tauri/Cargo.toml

bash hooks/install.sh
```

`install.sh` 는 세 가지를 하고, **하나라도 실제로 동작하지 않으면 실패로 끝냅니다.**

- `~/.claude/hooks/log_prompt.py` 를 레포의 파일로 **심볼릭 링크**합니다. 사본이 아닌 이유: **사본은 갈라집니다.** 훅을 고쳐도 고친 게 안 돌고, 몇 주 동안 그 사실을 모릅니다.
- `sweep.sh` · `archive_transcripts.py` · `recall-ingest` 를 `~/.claude/recall-bin/` 으로 **복사**합니다. 이번엔 심링크가 아닙니다 — **macOS TCC 는 `launchd` 에이전트에게 `~/Documents` · `~/Desktop` · `~/Downloads` · iCloud Drive 접근을 허용하지 않습니다.** 그 안에 클론한 레포를 가리키는 스위퍼는 매번 `Operation not permitted` 로 **조용히** 죽는데, `launchctl bootstrap` 은 성공을 보고합니다. 사본은 `launchd` 가 닿을 수 있는 곳에 둡니다. (사본은 갈라질 수 있고, **훅이 그걸 감시해 경고합니다.**)
- 매시간 스위퍼를 돌리는 `launchd` 에이전트를 등록합니다. 앱이 닫혀 있어도 세션 기록을 아카이브하고 응답을 수집합니다. **그리고 `install.sh` 가 기다렸다가 에이전트의 종료 코드를 확인합니다** — **"등록됐다"는 "돌았다"가 아니기 때문입니다.**

코드를 고치거나 레포를 옮긴 뒤에는 `bash hooks/install.sh` 를 다시 실행하세요 — 스위퍼는 사본입니다.

그다음 `~/.claude/settings.json` 에 훅을 등록합니다.

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 $HOME/.claude/hooks/log_prompt.py"
          }
        ]
      }
    ]
  }
}
```

> Claude Code는 훅 **설정**을 세션 시작 시 스냅샷하므로 다음 세션부터 적용됩니다. 훅 **스크립트 파일**은 호출할 때마다 다시 읽으므로, `log_prompt.py` 수정은 즉시 반영됩니다.

확인 — Claude Code에서 프롬프트를 하나 제출한 뒤:

```bash
sqlite3 ~/.claude/prompts.db "SELECT count(*) FROM prompts;"
```

### 2. Claude Code가 세션 기록을 너무 빨리 지우지 않게

Claude Code는 기본적으로 **30일**이 지난 세션 기록을 삭제합니다. Recall이 미처 수집하지 못한 응답은 그때 **영구히 사라집니다.** 여유를 두세요. `~/.claude/settings.json` 에:

```json
{ "cleanupPeriodDays": 90 }
```

Recall의 아카이브는 한 번 본 원본을 계속 보관하므로, 이 값은 "세션이 끝나고 스위퍼가 다음에 돌기까지의 틈"만 덮으면 됩니다. 다만 **큰 값은 디스크를 쓰고, 작은 값은 데이터를 잃습니다.**

### 3. 앱 빌드 및 실행

[Rust](https://rustup.rs/), Node.js, 그리고 **Python 3** 이 필요합니다 (macOS 에는 `/usr/bin/python3` 가 기본 포함). 훅과 아카이버가 모두 Python 이라, `python3` 가 `PATH` 에 없으면 훅은 **조용히** 아무것도 하지 않습니다 — 그 사실을 알려줬을 건강 검사까지 포함해서요.

```bash
npm install
npm run tauri dev      # 개발
npm run tauri build    # 프로덕션 번들 → src-tauri/target/release/bundle/
```

헤드리스 수집기는 1단계에서 이미 빌드했습니다. `~/.claude/recall-archive/archive.log` 에 `수집기가 없습니다` 가 보이면 스위퍼가 아카이브만 하고 수집은 못 하고 있다는 뜻이니, 다시 빌드하고 `hooks/install.sh` 를 재실행하세요.

macOS에서는 번들을 설치하고 격리 속성을 제거합니다 (adhoc 서명이라 없으면 Gatekeeper가 막습니다).

```bash
rm -rf /Applications/Recall.app
ditto src-tauri/target/release/bundle/macos/Recall.app /Applications/Recall.app
xattr -dr com.apple.quarantine /Applications/Recall.app
```

## 사용법

**평소에는 아무것도 누르지 않습니다.** 앱이 3초마다 확인합니다. 새 프롬프트는 저절로 나타나고, 응답은 Claude가 답하는 동안 채워집니다 — **턴이 진행 중일 때도** 실시간으로.

목록이 스크롤된 상태라면 새 프롬프트가 목록을 밀지 않습니다. 대신 **`새 프롬프트 N개 ↑`** 필이 뜹니다. 누르면 맨 위로 올라갑니다.

### 응답 읽기

응답은 **세그먼트**의 나열입니다.

| | |
|---|---|
| 산문 | 마크다운으로 렌더됩니다. |
| `▸ Bash cargo test --lib` | 도구 호출. **명령어가 라벨에 그대로** 보입니다. 누르면 전체 인자를 봅니다. |
| `▸ 결과 · 12 KB` | 도구가 돌려준 것. 크기와 함께 접혀 있습니다. **도구 본문은 열기 전까지 UI 로 보내지 않습니다** — 그래서 제 아카이브에서 가장 큰 응답(세그먼트 700개, 550KB)도 즉시 열립니다. 짧은 산문은 함께 보내고, 24KB 또는 400줄을 넘으면 펼칠 때 가져옵니다. |
| `▸ 백그라운드 작업 알림` | 백그라운드 에이전트가 끝나고 Claude가 작업을 이어간 지점. 별도 행으로 갈라지지 않고 **이 턴 안에 접혀** 있습니다. |
| `사용자가 중단함` | ESC를 눌렀던 지점. 그 전까지 Claude가 한 말은 **전부 남아 있습니다.** |

아주 긴 산문(붙여넣은 lockfile diff 같은 것)은 마크다운 대신 원문으로 렌더됩니다. 6만 줄을 마크다운으로 그리면 DOM 노드가 9만 개 생겨 창이 1초 넘게 얼어붙지만, 원문이면 노드 하나라 즉시 뜹니다.

### 버튼

**누를 일이 없어야 정상입니다.** 자동화가 틀렸거나 멈췄을 때를 위한 수동 탈출구로 남겨둔 것들입니다.

| | |
|---|---|
| `↻` | 3초를 기다리지 않고 지금 목록을 다시 읽습니다. |
| `⟳ 수집` | 스위퍼를 기다리지 않고 지금 전 세션을 다시 수집합니다. 세션 기록으로부터 `turn_segments` 와 `narrative` 를 다시 만듭니다 — `(prompt_id, src_uuid, block_idx)` 병합 키 위에서 **멱등**입니다 — 그리고 **`prompts.response` 는 절대 건드리지 않습니다.** 세션 기록이 사라진 세션은 건너뛸 뿐 비우지 않습니다. |
| `⤓ 24h` | 레거시. 최근 24시간의 응답을 옛 `prompts.response` 컬럼으로 다시 추출합니다. |
| `전체` | 레거시. **모든** 응답을 `prompts.response` 로 다시 추출하며 **덮어씁니다.** 먼저 DB를 스냅샷합니다. 무딘 도구이니 눈에 띄게 뭔가 잘못됐을 때만 씁니다. |
| `🧹 정리` | 응답이 없는 프롬프트를 삭제 후보로 올립니다. [삭제](#삭제가-위험한-작업입니다) 참조. |

## 어떻게 동작하는가

```
                     ┌──────────────────────────────┐
   프롬프트 제출 ──▶ │  UserPromptSubmit 훅         │
                     │  hooks/log_prompt.py         │
                     └───────────────┬──────────────┘
                                     │ payload 를 스풀에 먼저, 그다음 INSERT
                                     ▼
                          ~/.claude/prompts.db
                          prompts(prompt, cc_turn_id, …)
                                     │
                                     │ cc_turn_id ⟷ promptId 로 조인
                                     ▼
   Claude Code ────▶ ~/.claude/projects/**/*.jsonl   (cleanupPeriodDays 뒤 삭제)
   가 기록                           │
                                     │ 복사 + gzip
                                     ▼
                          ~/.claude/recall-archive/  (계속 보관)
                                     │
                                     │ 매시간 스위퍼 — 그리고 앱이 15초마다
                                     ▼
                          turn_segments(kind, name, body, …)
                                     │
                                     ▼
                              ┌─────────────┐
                              │   Recall    │
                              └─────────────┘
```

### 프롬프트를 자기 턴에 붙이기

**조용히, 미묘하게 틀리기 쉬운 부분**입니다.

Claude Code의 모든 훅 payload에는 **`prompt_id`** 가 있고, transcript의 모든 `user` 이벤트에는 **`promptId`** 가 있습니다. **둘은 같은 값입니다** — Claude Code 내부에서 같은 변수를 읽습니다. 훅이 이걸 `prompts.cc_turn_id` 로 저장하고, Recall이 그걸로 조인합니다. **시간창도, 텍스트 검색도 없습니다.** (다만 조인된 쌍에 **텍스트 정합성 검사**는 합니다: ID 와 프롬프트 텍스트가 어긋나면 키를 믿지 않고 매칭을 거부합니다 — `prompt_id` 는 Claude Code 내부의 **가변 전역**을 읽은 값이고, **확신에 찬 오답은 퍼지한 답보다 나쁩니다.**)

이게 중요한 이유: **텍스트 비교는 동작하지 않습니다.** 커스텀 슬래시 커맨드는 DB에 `/my-skill` 로 저장되지만 transcript에는 `<command-name>/my-skill</command-name>` 로 확장됩니다. 텍스트로 맞추면 놓칩니다. **ID로 맞추면 상관없습니다.**

> **`promptId` 는 *턴* ID 이지 프롬프트 ID 가 아닙니다.** 전역 유일하지 않습니다 — 서브에이전트 transcript가 부모의 것을 물려받고, 연달아 입력한 두 프롬프트가 하나를 공유할 수 있습니다. **절대 `UNIQUE` 인덱스를 걸지 마세요.** 진짜 프롬프트가 조용히 사라집니다.

훅이 `cc_turn_id` 를 저장하기 전에 쌓인 행은 옛 휴리스틱(캐시된 transcript uuid → ±30초 시간창 + 텍스트 접두 보정)으로 폴백합니다. 어느 경로로 매칭됐는지는 `prompts.match_kind` 에 기록됩니다.

### 턴이 어디서 끝나는지 판정하기

> **transcript의 `user` 이벤트가 턴을 소유하는 조건 = `UserPromptSubmit` 이 발생했다는 것** = `prompts` 행이 존재한다는 것.
>
> **훅이 발생했다는 사실 자체가 "사람이 입력했다"의 근거입니다.**

그 외 전부 — 백그라운드 에이전트 알림, 내장 슬래시 커맨드, `!bash` 줄, ESC 중단 — 는 **자기가 끼어든 턴 안으로 접힙니다.** 그래서 프롬프트 하나가 완결된 이야기 하나가 됩니다.

당연해 보이는 대안(transcript의 `promptSource` 필드로 거르기)은 **틀렸습니다.** 실제 DB와 대조해보니 **133개 세션 중 21개에서 프롬프트를 놓쳤습니다.**

### 왜 `Stop` 훅이 없는가

가장 자연스러운 설계는 `Stop` 훅을 걸어 턴이 끝나는 순간 응답을 잡는 것입니다. 실제 프롬프트 약 1,700개로 측정한 결과, 그 설계는 **약 10%를 잃습니다.**

- **턴이 중단되면 `Stop` 이 발생하지 않습니다** — ESC를 눌렀거나, 세션이 죽었거나, 컴퓨터가 잠들었을 때. 그런 턴에도 **중단 전까지 Claude가 한 말이 전부 들어 있습니다.**
- **프롬프트의 13%에서 `Stop` 이 두 번 이상 발생합니다.** 백그라운드 에이전트 알림이 턴이 끝난 *뒤에* 도착하고 Claude가 작업을 이어가기 때문입니다. 첫 `Stop` 에서 순진하게 체크포인트를 잡으면 나머지를 버리는데, **그게 그 턴들 내용의 60%** 입니다.

즉 **스위퍼는 어차피 필요합니다.** 그리고 스위퍼가 있으면 훅이 사는 것은 **지연 시간뿐**인데, 그 대가는 **주력 도구의 모든 턴에 영원히 붙는 작업**입니다. 전체 transcript를 처음부터 다시 읽는 것은 **몇 초**짜리 작업이고, 시간당 한 번 백그라운드에서 낮은 I/O 우선순위로 돕니다. (측정 시점 기준 391MB 에 2.2초, Python. 아카이브는 자라고 그 수는 줄지 않습니다.) **훅을 걸 가치가 없습니다.**

스위퍼에는 **바이트 커서도 없습니다.** 파일을 통째로 다시 파싱하고 `(prompt_id, src_uuid, block_idx)` 로 병합합니다. **잘못 놓을 수 있는 커서는 턴의 뒷부분을 조용히 날릴 수 있는 커서입니다.** 아예 없으니 그럴 수가 없습니다.

**스택:** Tauri 2 (Rust) + React 19 + TypeScript. Rust는 속도 때문이 아니라 **브라우저 샌드박스가 `~/.claude` 를 읽을 수 없기 때문에** 있습니다.

## 내 데이터

Recall은 완전히 오프라인입니다. 모든 것이 `~/.claude/` 안에 있습니다.

| 경로 | 접근 | 내용 |
|---|---|---|
| `prompts.db` | 읽기 **및 쓰기** | 프롬프트, 응답, 세그먼트, 북마크와 태그 |
| `projects/**/*.jsonl` | **읽기 전용** | Claude Code 자신의 세션 기록. **Recall은 여기에 절대 쓰지 않습니다.** |
| `recall-archive/` | 쓰기 | 세션 기록의 gzip 사본. 보존 시계 밖에 둡니다 (원본의 약 30% 크기) |
| `recall-backups/` | 쓰기 | **모든 삭제**(단건이든 대량이든)와 대량 덮어쓰기 **전에** 뜨는 DB 스냅샷. 자동 스냅샷은 최근 10개만 보관하고, **손으로 만든 백업은 절대 지우지 않습니다.** |
| `recall-spool/` | 쓰기 | DB에 도달하지 못한 프롬프트. 평소엔 비어 있습니다. |

### 스키마

`prompts` **와 `capture_health`** 는 훅이 만듭니다 — **앱을 한 번도 켜지 않은 상태에서도 경보를 울릴 수 있어야 하기 때문입니다.** 나머지는 앱이 첫 실행 때 만들고, `prompts` 에 `msg_uuid` · `kind` · `narrative` · `match_kind` · `ingest_ver` 컬럼을 덧붙입니다.

```sql
prompts(id, session_id, cwd, prompt, created_at,
        response,          -- 레거시 텍스트. 동결: 자동화가 다시 쓰지 않습니다.
        msg_uuid,          -- 레거시: 캐시된 transcript 이벤트 uuid
        cc_turn_id,        -- = 훅의 prompt_id = transcript 의 promptId
        transcript_path,
        kind,              -- 'human' | 'system' (주입 이벤트, 목록에서 숨김)
        narrative,         -- 산문만 평탄화한 것. 검색이 이걸 훑습니다.
        match_kind,        -- 'exact' | 'uuid' | 'fuzzy' | 'conflict'
        ingest_ver)

turn_segments(prompt_id, src_uuid, block_idx, seq,
              kind,        -- text | tool_use | tool_result | injected | interrupt | image
              name, tool_id, preview, body, nbytes, nlines, is_error, ts)
              -- UNIQUE(prompt_id, src_uuid, block_idx) 가 병합 키입니다. 그래서 같은 transcript 를
              --   다시 수집해도 멱등이고, 파서를 고쳐도 행이 중복되지 않습니다.

segment_edits(prompt_id, src_uuid, block_idx, body, edited_at)  -- 내 것. 자동화가 건드리지 않습니다.
ingest_state(session_id, src_mtime, ingested_at)                -- "이 transcript 가 자랐는가"
capture_health(id, problems, checked_at)                        -- 훅이 쓰고 앱이 읽습니다

cwd_aliases(cwd, alias, updated_at)
prompt_bookmarks(prompt_id, created_at)
tags(id, name, created_at)
prompt_tags(prompt_id, tag_id)
prompt_responses(prompt_id, response, fetched_at)               -- 레거시 캐시
```

### 안전 규칙

> **훅은** 새 `prompts` 행과 `capture_health` 를 씁니다.
> **수집기는** `turn_segments` · `ingest_state` 와, **이미 존재하는** `prompts` 행의 `narrative` · `kind` · `match_kind` · `ingest_ver` 컬럼만 씁니다 — 그 외에는 아무것도 쓰지 않습니다.
> **사람은** `prompts.response` 와 `segment_edits` 에 씁니다.
> **수집기에서 사람이 쓴 바이트로 가는 코드 경로는 존재하지 않고, `ingest.rs` 에는 `DELETE` 문이 없습니다.**

`prompts.response` — 예전 버전이 추출해 둔 텍스트 — 는 **자동화가 다시는 손대지 않습니다.** 세션 기록이 이미 삭제된 프롬프트에게는 **그것이 영원히 유일한 사본**입니다. 완전본 수집은 **아직 존재하지도 않던 테이블**에 들어갔으므로, 업그레이드가 파괴할 것이 없었습니다.

### 삭제가 위험한 작업입니다

프롬프트 편집은 `UPDATE` 입니다. 삭제는 진짜 `DELETE` 이고, **휴지통이 없습니다.**

`🧹 정리` 는 무언가를 삭제 후보로 올리기 전에 **부재의 적극적 증거**를 요구합니다.

1. 세션 기록을 **찾았고**,
2. 그 턴에 응답이 **없음을 확인했고**,
3. 프롬프트가 **48시간** 이상 됐고,
4. **북마크도 태그도 없고**,
5. **세그먼트도 없을 것.**

세션 기록이 없거나 조회가 실패했다면 그 프롬프트는 `unknown` 이며 **삭제 대상이 아닙니다. 증거의 부재는 부재의 증거가 아닙니다.**

이 구분은 학술적인 이야기가 아닙니다. 예전 버전은 *"복구를 시도했는데 실패했다"* 를 *"지워도 안전하다"* 로 해석했고, 복구 경로의 버그 하나가 그것을 **프롬프트 438개 삭제**로 바꿨습니다. `recall-backups/` 의 스냅샷이 그것들을 되살린 **유일한** 수단이었습니다.

대량 삭제나 대량 덮어쓰기 전에는 DB를 스냅샷합니다 (`VACUUM INTO` 라 쓰기가 진행 중이어도 일관됩니다). **백업이 실패하면 아무것도 지우지 않습니다.** 되돌리려면 스냅샷을 `~/.claude/prompts.db` 로 복사하세요.

## 수집 상태 경고

수집은 **조용히 실패하도록** 설계돼 있습니다. 훅이 죽으면 사용자 프롬프트 밑에 트레이스백이 뜨는데, **프롬프트 기록기가 프롬프트 입력을 방해하는 건 어떤 이유로도 정당화되지 않습니다.** 그런데 그건 **모든** 실패가 조용해진다는 뜻이고, 조용한 실패는 **30~90일 뒤 데이터 부재로만** 드러납니다 — 그때는 세션 기록이 이미 삭제됐습니다.

그래서 알람을 **피할 수 없는 경로**에 둡니다. `UserPromptSubmit` 의 stdout은 **Claude의 컨텍스트에 주입되므로, Claude가 직접 말합니다.**

```
[Recall 수집 상태 경고 — 사용자에게 알려주세요]
- Recall 이 4일째 응답을 수집하지 못했습니다
- 세션 기록 아카이브가 4일째 갱신되지 않았습니다 (launchctl list | grep recall 확인)
```

감시 대상: **스풀 적체**(프롬프트가 DB에 못 들어가고 있다 — 최악입니다. **프롬프트는 디스크의 어떤 것으로도 재생성할 수 없습니다**), 스위퍼 정지, 디스크 부족, 수집 정체. 한 시간에 한 번까지만 알립니다.

앱은 같은 경고를 **닫기 버튼 없는 배너**로 띄웁니다. 스쳐 보내는 토스트가 아니라 *"지금 데이터가 사라지고 있다"* 는 신호이고, **고쳐야 사라집니다.**

**가장 중요한 검사들은 의도적으로 DB 없이도 돕니다.** 스풀 적체·정지한 스위퍼·갈라진 스위퍼 사본·꽉 찬 디스크는 파일시스템만 봐도 알 수 있고, **DB 자체가 망가졌을 때 남는 신호는 그것뿐**입니다. (수집 *정체* 검사만은 DB 가 필요합니다. DB 를 못 열면 이 검사와, 앱 배너에 쓰이는 `capture_health` 기록을 건너뜁니다 — 그때 남는 채널은 stdout 뿐이며, **그것이 이 설계의 요점입니다.**)

## 알려진 한계

- **Claude Code는 자신의 추론을 저장하지 않습니다.** transcript의 모든 `thinking` 블록은 본문이 비어 있고 불투명한 signature만 남습니다. "Claude가 말한 전부"에는 **어떤 설계로도 못 뚫는 천장**이 있습니다.
- **훅 설치 이후의 프롬프트만 나타납니다.** 기존 transcript에서 소급해 채우지 않습니다.
- **응답이 없는 프롬프트는 대개 버그가 아니라 정상입니다.** Claude가 답하기 전에 ESC로 턴을 취소했다면 보여줄 응답이 정말로 없습니다.
- **서브에이전트 transcript는 아카이브되지만 수집되지는 않습니다.** 에이전트가 *보고한 것* 은 잡힙니다(도구 결과로 들어옵니다). *내부에서 한 일* 은 아카이브에는 있지만 앱에는 없습니다.
- **세션은 첫 작업 디렉터리로 묶입니다.** 세션 중간에 `cd` 해도 그 세션의 모든 프롬프트는 시작한 곳에 남습니다.
- **검색은 `LIKE` 스캔입니다** (프롬프트 + 산문 평탄화 + 레거시 response 컬럼). 지금 규모에선 괜찮지만 영원히 괜찮진 않을 것입니다.
- **훅은 레포로의 심볼릭 링크입니다.** **다른 브랜치를 체크아웃하면 다음 프롬프트에 도는 훅이 바뀝니다.** 낡은 사본이 도는 일을 영원히 막는 대가입니다.
- **macOS 전용입니다.** Tauri 앱 자체는 다른 곳에서도 빌드되겠지만, `hooks/install.sh` 는 `launchd` 에이전트를 설치하며 Linux/Windows 대응물이 없습니다 — **앱이 닫혀 있을 때 응답을 수집하는 유일한 경로가 스위퍼**입니다. 직접 `hooks/sweep.sh` 를 스케줄링해야 합니다.
